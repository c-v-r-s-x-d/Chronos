# Chronos 1.0.0

The first release.

## What it does

Chronos blocks the sites and apps you pick, on Windows, for as long as you say. You can end a
session early, but only by asking and then waiting a cool-down you chose before it started.
Closing the window, stopping the service or rebooting doesn't lift the block.

- **Sites** are blocked three ways at once: the `hosts` file, Windows Filtering Platform address
  filters, and a DNS resolver on `127.0.0.1:53`. Each says when it can't work on this machine, and why.
- **Apps** are closed as they start, by name or by exact path; a small window says so.
- **The tray app** has four sections (Session, Sites, Apps, Settings), an hourglass that runs with
  the session, ready-made sets of sites, an "Add application" dialog (running programs, an `.exe`,
  a shortcut or a name), English and Russian, light and dark themes.
- **The command line**, `chronos.exe`, does the same plus repair: `recover`, `clean`, `diag`.

## Requirements

- Windows 10 or 11, 64-bit. The installer carries its own .NET runtime.
- Administrator rights to install.

## Installing

Run `Chronos-1.0.0.msi`. Chronos opens when the installation finishes, and starts with Windows
from then on.

The installer isn't signed, so SmartScreen warns about an unknown publisher: choose **More info**,
then **Run anyway**. To check the file first:

```
certutil -hashfile Chronos-1.0.0.msi SHA256
```

and compare with `SHA256SUMS`.

Removing: `msiexec /x Chronos-1.0.0.msi` keeps your lists and logs; add `REMOVEDATA=1` to remove
them too. Settings > Apps works as well.

## Known limitations

- A VPN that resolves names through its own tunnel can bypass the DNS layer; some drop local DNS
  queries entirely. Chronos then reports the DNS layer as unavailable and blocks sites through
  the other two.
- Installing a newer version during a session ends that session.
- The bundled .NET runtime is updated with new Chronos releases, not through Windows Update.
- Not yet tried on a live machine: a reboot, sleep or a network change during a session. They
  are covered by tests only.

The full list is in [docs/operations.md](../operations.md#known-limitations).
